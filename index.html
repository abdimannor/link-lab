Link Lab

One link has several states, and four short CSS rules decide which colour wins. This lesson shows the five states, why their order matters, and what a link owes the people who use it.

You will be able to

  • Style :link, :visited, :focus-visible, :hover and :active.
  • Put the rules in an order where every state can show.
  • Explain why :visited is limited and why focus must stay visible.

The core idea

Why the order matters

All five selectors have the same specificity. When several states match at once, the rule written last wins. Remember it as LoVe HAte: link, visited, hover, active. Simplified colour names below; the page uses the exact values in its <style> block.

  1. a:link {
  color: green;
}

    First: the base colour of a link that has not been visited.

  2. a:visited {
  color: pink;
}

    Second: overrides :link once the page has been opened. Browsers only let it change colours, for privacy.

  3. a:focus-visible {
  outline: 3px solid blue;
}

    Third: the keyboard state. Placed before :hover so pointer states still win.

  4. a:hover {
  color: red;
}

    Fourth: comes after :visited, so a visited link still turns red under the pointer.

  5. a:active {
  background: yellow;
}

    Last: a pressed link is also hovered, so :active must come after :hover or it would never show.

        Going further

        Why :visited keeps a secret

        The order section says browsers only let :visited change colours. Here is why. A page could once draw hundreds of hidden links to other sites, style :visited differently and ask the browser which ones had changed. That read your browsing history in milliseconds, without asking. Browsers closed the hole in two ways, described on MDN's Privacy and the :visited selector.

        1. Only colours

        A visited link may change only these properties: color, background-color, border-color (and its sub-properties), column-rule-color, outline-color, text-decoration-color, text-emphasis-color, and the colour parts of SVG fill and stroke. Size, position and layout never change, so nothing measurable moves. Even a difference in transparency between the two states is ignored.

        2. Scripts are told a white lie

        getComputedStyle and similar functions always answer as if the link were unvisited. A sibling selector such as :visited + span also styles the span as if the link were unvisited.

        Focus: the state the keyboard sees

        :focus matches whenever an element has focus, however it got there. :focus-visible matches only when the browser decides, by its own heuristics, that the focus should be shown, which in practice usually means keyboard focus and not a mouse click on a link or button (MDN: :focus-visible). That is why this page styles :focus-visible: keyboard users get a clear ring, mouse users are not shown a ring after every click.

        Click a button below with the mouse, then press Tab to reach the next one. The log shows what the browser matched.

          Never remove focus without a replacement

          The third button above has outline: none and no other style. With a keyboard you cannot tell when it has focus. WCAG 2.4.7 Focus Visible (Level AA) asks that any keyboard operable interface has a mode where the keyboard focus indicator is visible. If you remove the default outline, put something at least as clear in its place.

          And do not hide it behind your own content

          WCAG 2.4.11 Focus Not Obscured (Minimum) (Level AA) says a focused component must not be entirely hidden by content the author created, such as a sticky header or a cookie banner.

          Links that tell the truth

          Screen readers can list every link on a page, out of context, the way a sighted reader skims. In that list ten links called "read more" (or "läs mer") are ten identical lines. A link's text should say where it goes.

              target="_blank" and rel

              The 2023 exercise opened its three links with target="_blank" and nothing else. A page opened that way used to get window.opener, a handle back to the page that opened it, which it could use to send that tab somewhere else. rel="noopener" removes the handle. MDN notes that today target="_blank" on <a> implicitly behaves like rel="noopener" (MDN: rel=noopener). rel="noreferrer" goes further: the browser leaves out the Referer header and also behaves as if noopener were set (MDN: rel=noreferrer). The three links at the top carry both, which still helps in older browsers and keeps the source of a click private.

              <a href="https://info.cern.ch/" target="_blank" rel="noopener noreferrer">The first website</a>

              A new tab is still a surprise for some people, so it is kind to say so in the link, as a word or hidden text.
